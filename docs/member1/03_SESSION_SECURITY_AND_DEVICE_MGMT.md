# ExamForge — Session Security & Multi-Device Governance Specification
## Member 1 Deliverable: Session Hijacking Defense and Device Fingerprinting

**Document Reference:** EF-SEC-M1-SES-2026-V1
**Applicability:** University Examination Management Subsystem

---

### SECTION 1: SESSION STATE MACHINE AND REVOCATION PROTOCOL 1

**Clause 1.1 [Concurrent Device Restraint]:**
To protect institutional examinations from unauthorized multi-location credential sharing, each authenticated faculty or administrative user is constrained to a maximum of 3 concurrent sessions. Exceeding this boundary triggers automated eviction of the least-recently active device session accompanied by an audit alert.

**Clause 1.2 [Inactivity Expiry and Sliding Heartbeat]:**
Authenticated REST sessions enforce a strict 30-minute idle inactivity timeout. Client applications transmit periodic heartbeats during user interaction. If no user interaction is detected within 1800 seconds, the backend invalidated session cannot be refreshed without complete password re-authentication.

**Clause 1.3 [Cryptographic Token Binding]:**
Tokens are bound to client user-agent digests and IP subnets. In the event of an abrupt network route alteration during privileged examination grading or timetable validation, the session security manager flags an anomalous IP leap and forces secondary verification.
